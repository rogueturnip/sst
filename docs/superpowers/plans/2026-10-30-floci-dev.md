# Floci dev backend implementation

**Goal:** Complete the supplied Floci design for the first supported SST component set, following the compatibility spike.

**Scope:** Explicit `sst dev --floci`; pinned Docker lifecycle; static AWS credentials and endpoint guards; instance-separated local state; preflight and runtime compatibility enforcement; authenticated local bridge; Function URLs, Bucket, Dynamo and Queue subscribers; example, docs and isolated integration CI. Cloud behavior remains unchanged.

## Review decisions

- Reject unverified Floci versions rather than silently use an unverified compatibility profile.
- Reserve instance identity in memory before preview; persist it only after compatibility succeeds. Never change an active project's state root on an initialization race.
- Use separate preflight reports and dev-server discovery files per run/endpoint to prevent concurrent targets from sharing results.
- Reject non-live Functions in the initial profile. Arbitrary user code is not sandboxed; CI verifies a strict network boundary separately.
- Keep existing developer containers and resources. CI cleanup is explicit and restricted to the harness's uniquely named resources.
- Preserve cloud AppSync behavior. Only Floci uses the new transport and marks its bearer token as a secret in state.
